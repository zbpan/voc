## 运行

在本目录执行`python run.py`，访问 <http://127.0.0.1:8765>，按Ctrl+C停止。Windows也可执行`start.ps1`及`stop.ps1`。

首次安装依赖，在本目录分别执行：

```powershell
python -m pip install -r requirements.txt
npm ci
npm run build
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

需要 Python 3.11+、Node 22.12+、FFmpeg/ffprobe（在PATH中）。开发时后端运行 `python run.py`，前端运行 `npm run dev`，前端开发地址为 `http://127.0.0.1:5173`。

## 配置

在模型配置页设置，或在启动前导出`QWEN_API_KEY`、`QWEN_BASE_URL`、`QWEN_MODEL`和`QWEN_REGION`。页面保存优先于环境变量，密钥保存在本机数据目录的明文配置中且不会由读取接口回显。应用不再默认读取个人集中凭据。

可选：`VOC_DATA_DIR`指定数据目录，`VOC_PORT`指定本机端口。数据默认保存在`app/runtime/`。`VOC_CREDENTIALS_FILE`仅在显式设置时读取外部dashscope格式凭据，文件应在仓库外。

## 使用顺序

1. 在「门店与采集」新建门店，或者直接添加未分配反馈。
2. 点击「添加反馈」，批量上传录音、直接录音或粘贴文字。客服通话可选客户左/右声道。
3. 在「原声收件箱」查看排队和分析进度。失败任务可查看原因并重试，成功片段会被复用。
4. 打开反馈详情，回听原声、阅读逐段转写、确认主题和严重度；录入跟进人、状态及记录。
5. 在「洞察报告」按顶部的门店、日期及原文搜索范围生成报告，下载Markdown文件。
6. 每家门店有独立采集链接和二维码，可收集语音或文字。本机模式仅供本机体验；跨设备采集需另行部署至可访问的HTTPS地址。

## 数据口径与当前边界

- 反馈数是原始记录数，事件数是一条反馈中提取的独立体验事件数，二者不能混用。
- 负向占比的分母是已完成且包含体验反馈的记录，分子包含负向与褒贬并存。模型被要求识别普通语句、新闻、小说等非体验内容；本轮公开中英文普通语句均未误生成投诉。
- 默认事件统计排除人工「已排除」事件。高严重度待跟进包括高/紧急且未解决的有效事件，可能仍待复核。
- 日期筛选按UTC接收日期；界面时间按浏览器本地时区显示。趋势图最多展示最近90天，筛选范围内总数不受图表窗口限制。
- 音频转换成16kHz单声道，按120秒连续片段分析。回听位置来自真实分段边界，**不是字级时间戳**。同一主题、同一句引用的事件跨片段合并；跨片段不同表述仍可能需要人工合并判断。
- 混合声道角色由模型判断，无法确认时标记「身份待核实」，不等同于专业说话人分离；左右声道由用户指定。
- 单文件≤512MB、≤3小时；网页录音≤5分钟；批次≤20个文件。队列为单worker，重启恢复未完成任务。
- 报告按严重度优先引用最多200条有效事件，明确显示抽样覆盖范围；数量来自数据库快照，建议由模型生成。删除原记录后历史报告仍保留生成时证据文本，但原声链接将不可用。
- 这是绑定127.0.0.1的本机MVP，工作空间用于数据整理，尚无账号认证或面向公网的租户权限体系。没有支付、订阅或收费模块。


## CXO经营总览

首页“经营总览”展示等长周期对照、负向反馈变化、门店议题矩阵、客群、正向体验、决策事项与管理行动前后观察。公开演示入口：<http://127.0.0.1:8765/?workspace=open-source-demo>。

经营聚合按全量记录计算，支持门店、原文搜索和7/20/30天窗口，默认锚定该空间最新反馈日期。点击指标、议题、门店矩阵或行动证据可下钻到全部关联反馈，再回听原声。界面的“统计口径”说明分母、去重、排名、人工标签和演示设定。

“导出经营简报”输出确定性计算及完整反馈索引。“洞察报告”使用Qwen生成管理层建议，并保留全量经营快照；最多200条事件引用的限制仅作用于模型证据候选。经营总览的行动计划目前由数据导入提供，事件复核与跟进仍在“体验事件”编辑。

演示数据详情见`../examples/README.md`。聚合从数据库现算；排除事件不会自动重写反馈情绪，完整规则见界面口径。
